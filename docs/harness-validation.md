# Local harness validation

Validated on Linux on 2026-10-08 under the pinned Nix environment. Implementation is tracked in [issue #7](https://github.com/jens-hj/relay/issues/7).

- Settings detected the existing local Codex 0.161.0 and Claude Code 2.1.291 installations as authenticated. Read-only probes did not run model turns or expose login output. The Nix Claude Code fallback (2.1.193) also built successfully.
- From a fresh database, `just dev` opened native project setup. Entering the server checkout, `jens-hj/relay`, project owner `jens-hj`, and board 5 through the form saved the binding and synced the real board. Closing the window stopped its server; restarting the same recipe reopened the saved board with unchanged workspace revision, without board environment variables.
- Both real harnesses completed initial turns, resumed their exact saved thread/session, and consumed an inline image followed by a text file at their recorded positions. Both identified the blue image and the file's token; these read-only turns left no worktree changes.
- A real Claude Ask turn requested permission for its Write tool. Relay recorded the exact run/request, accepted Allow once, and returned the native control response. Claude then created only the requested smoke file in its isolated worktree, completed, and produced the expected one-file review diff. Nothing was integrated, committed, or pushed from these workers.
- Native Settings was inspected under Xvfb with Mesa software Vulkan at 2× display scale. Both harness cards, executable details, project setup, and existing appearance controls rendered. Headless tests exercise refresh, exact inline permission commands, and expired-request removal.
- `just check` passes: 100 tests (4 core, 38 desktop, 49 server unit/runtime, 9 HTTP workspace), strict all-target Clippy, Rust/Mosaic/just/Nix formatting, and native-system flake evaluation. Protocol subprocess tests cover all Codex execution policies, Claude modes/resume/multimodal/permission/stop, background-work completion, saved configuration, and schema 4 compatibility with older threads and explicit/custom profile settings.

Native execution and rendering were verified on Linux only. Harness readiness means installed/authenticated; account, managed policy, model access, and mode support can still fail at launch. Ask presents supported native tool requests; other interactive harness features are not exposed. The Claude control protocol follows the CLI/SDK streaming interface and was validated against the installed version above. Autonomous director execution, GitLab sync, and context compaction/reset remain later work.

Workflow responsibilities and completion criteria do not individually constrain tools. Execution modes configure native harness protections; Unrestricted Access deliberately bypasses those protections. Existing process-group/restart guarantees remain in effect, including Linux parent-death cleanup, without guaranteeing descendants that deliberately escape their group.
